# Comparison with the built-in graph view

Measured 2026-10-15 on one MacBook, Obsidian 1.14.4 (Electron 43, Chromium 150), in a separate Obsidian instance on a throwaway copy of each vault (bench/obsidian-cdp, docs/dev-testing.md). The built-in graph ran first with community plugins off; then ours. Same scripted input for both. **One run per cell: expect noise.**

## What was done
1. Open the graph view with its command. Take small screenshots about every 300 ms to find the first time the pane shows content ("first visible") and the first time the picture stops changing ("visually stable").
2. Record the main thread's busy time (Chrome DevTools `Performance.getMetrics`), long tasks (over 50 ms) and the worst gap of a 20 ms timer.
3. Interaction: 30 wheel steps in, 30 out, then a 30-step drag-pan. Record the interval between animation frames and long tasks.
4. JS heap after a forced garbage collection, before opening and when stable.
"Ours, cold" = no saved layout. "Ours, cached" = reopened with the saved layout (exact restore).

## Reading the numbers fairly
- Our 8.3 ms frame interval is the display's refresh rate (about 120 Hz): it means no dropped frames, not that we are "x times faster" than that.
- The big differences are main-thread busy time, long tasks, interaction smoothness and memory. Time to a settled picture is a smaller gap (10 s against 14.6 s; 4.1 s against 6.6 s). The very fast opens come from the layout cache, which the built-in graph does not appear to have.
- **Not measured:** worker-thread and GPU use (our layout runs in a Web Worker; the built-in graph's threading is unknown), battery, mobile, memory outside the JS heap.
- **The cameras differ.** The built-in graph opened zoomed in on a small region with every label drawn, not fitted to the whole graph. Ours fits everything (with bubbles). So the interaction tests did different drawing work at the start. This favours neither side cleanly.
- **Synthetic vault.** Random links with a few hubs, no communities, generated by bench/generate-vault.mjs. Real vaults differ. The built-in graph's defaults on your real vaults may differ from what it showed here.
- **Test setup:** the core Graph view had to be switched on in the throwaway instance (it was off in these vaults). An earlier attempt measured nothing because of that and was discarded.
- **Only the plugin's default settings were used**, with the "Cluster when zoomed out" bubbles on.

## Where the built-in graph is better or we are missing things
- **Features:** its search is Obsidian's full search (including note content and more operators); it can show tags as nodes; its local graph has backlink and outgoing toggles; it has link and node options we have not copied. See docs/behaviour-spec.md.
- **Look:** it labels nodes at its default zoom. Our zoomed-out view is grid bubbles, which show density rather than real communities, and the grid is visible.
- **Maturity:** years of use on many vaults and platforms; ours is untested on mobile and on real vaults beyond a few quick checks.
- **Cold settle:** only about 1.5 times faster than the built-in's visual settle in this test, not an order of magnitude.
