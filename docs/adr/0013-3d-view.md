# ADR 0013: Optional 3D view: octree layout in Rust, custom WebGL2 renderer, no library
- Status: accepted (user request 2026-10-15)
- Date: 2026-10-16

## Context
The user wants the graph shown on three axes when a setting is on, off by default, working with skins (galaxy, brain). The brief's architecture (Rust layout in a worker, thin TypeScript) must hold, and nothing may be added to the 2D path's behaviour.

## Options
1. Reuse the 2D layout and fake depth. 2. A real 3D layout (octree) plus a library renderer (three.js, about 400 to 700 KB, new dependency, more for the community review). 3. A real 3D layout plus a small custom WebGL2 renderer.

## Choice
Option 3.
- Layout: `core/src/layout3d` (`Layout3`) and `core/src/barnes_hut/octree.rs`. Same d3-force model and parameters as 2D, plus z; the 2D `Layout` and quadtree are untouched (duplication accepted so 2D cannot regress). Start positions spread evenly through a sphere (R2 low-discrepancy sequence, seeded offset and jitter). Wasm grew from 36 KB to 57 KB.
- Renderer: `render/renderer3d.ts`, about 450 lines, no dependency. Nodes are GPU point sprites sized by perspective (soft halo for glow skins), links are GPU lines faded with distance, galaxy stars are a fixed point field that follows only the camera rotation, labels and the hover ring go on a 2D overlay. Hidden nodes have size 0; links are an index buffer over the shared position buffer, rebuilt when visibility changes.
- Camera and picking: `render/math3d.ts` (matrices, orbit camera, projection, nearest-node picking, view-plane unprojection), unit-tested. Picking is on the CPU (project every shown node, nearest on screen within its radius): about 0.2 ms at 10k.
- View: one `GraphView` with a dimension (2 or 3). Positions are stored per dimension; the existing filter, group, local-graph, cache and hover pipeline is shared. The transparent 2D canvas stays on top as the event surface; the WebGL canvas and overlay sit under it. Dragging a node in 3D moves it in the plane that faces the camera.
- Cache: format version 2 stores the dimension; 3D positions go to `layout-cache-3d.bin` (20 bytes per node).
- Controls: drag turns, right-drag or a modifier key slides, wheel and pinch zoom, double-click fits. Optional slow auto-rotation.

## Consequences
3D needs WebGL2 (present in Obsidian's Chromium; mobile untested). If a context cannot be created, the view shows a notice and stays in 2D. Draw time reported in the status line is CPU submission time, not GPU time. Lines are one device pixel wide (WebGL does not guarantee thicker lines). A shader precision mismatch (vertex highp against fragment mediump on a shared uniform) was caught on the first real run and fixed.
